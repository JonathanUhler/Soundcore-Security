# Style Guide

This document is the primary style guide for the Soundcore project. Currently it only covers written
prose, but will be extended in the future to cover code as well.

## Written Prose

Regular text written for this project should follow these conventions:

- Strict 100 character limit on lines. The exceptions to this rule are long inline codeblocks in
  markdown documents, (hyper)links, and markdown tables
- All levels of markdown headers should use Title Case
- Conservative use of text formatting. **Bold**, *italics*, ~~strikethrough~~, and other formatting
  on normal text should be used sparingly (not more than once every few paragraphs). New sections
  should start with markdown `#` headers, rather than boldface titles.
- Conservative use of sentence-joining punctuation. Dashes, semicolons, and colons should be used
  carefully. Regardless of if text is generated by an AI agent, those punctuation types make it easy
  to create long and rambling sentences. Dashes and semicolons should always be restructured to use
  periods or commas instead. Colons should only be used with lists
- Terseness is okay and even preferred. The goal of documentation in this project is to explain
  technical concepts with high levels of detail without rambling for paragraphs

## When You're Unsure

When in doubt, ask for clarification about a style decision. If you're an AI agent acting
autonomously, you can deduce unstated style conventions from existing documents, and should then
recommend updating this style guide to explicitly state the missing convention.
